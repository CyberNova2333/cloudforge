## 反证与后续问题

反证检查（Falsifying check）：若 `git-http` 测试允许只读/部署令牌越权改写默认分支、若 `AgentReviewer` 在无绑定或超出预算时未安全终止并允许修改受保护工作区外文件、或若 `access_runtime_state` 缺行时业务路由未返回 503，则上述核心架构结论需立即修订。

下一位读者可能问（Next reader question）：未来的多团队与五级仓库角色模型（`read` / `triage` / `write` / `maintain` / `admin`）何时才会开放？目前数据库中仅存在 `compat-v1` / `runtime-bridge-v1` 预检与拒绝开关（`rolePublishingAllowed: false`），后续开发顺序与验收矩阵以 [权限设计草案](../../docs/team-access-design.md) 为准。

## 范围与未验证事项

本指南包覆盖 CloudForge 服务端 Worker（Git/LFS、AI 审查、堆叠与自动合并、Actions 容器、Webhooks、身份与 OIDC、MCP 网关、权限运行时与运维工具链）。生产环境中具体 Cloudflare 账户配额、线上真实邮件投递及多容器镜像冷启动耗时不在本地文档校验覆盖范围内，对应运维操作需以真实 `wrangler` 与 `pnpm cloudforge` 执行日志为准。
