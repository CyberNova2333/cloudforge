# 身份认证与账户恢复

本设计对应路线图第二阶段。代码已包含成员自愿 TOTP、一次性恢复码、敏感操作重验、管理员强制 MFA 策略、OIDC 显式绑定及已有绑定的 SSO 登录；通行密钥仍按下文边界规划。代码实现、配置发布和生产启用分别核验。

## 第一版的认证边界

CloudForge 仍是单租户实例。人的网页身份来自 better-auth 的 D1 会话，Git/LFS 的个人访问令牌、仓库部署令牌及 MCP OAuth 凭据分别验证。代理账号不能取得人的会话或认证因子。

| 入口                               | 第一版行为                                                                                                        |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 用户名或邮箱 + 密码                | 未启用 TOTP 时维持原流程；已启用时必须再完成 TOTP 或恢复码挑战，之后才允许访问账户和完成 OAuth 授权               |
| 账户设置 → 安全                    | 输入当前密码生成待验证的 TOTP；首次验证码确认后启用；显示一次恢复码                                               |
| 更换恢复码、关闭 TOTP              | 当前密码与最近完成的第二因子验证共同授权；证明绑定当前会话、有时限、只供一次敏感操作                              |
| 现有网页会话                       | 启用时撤销旧会话，保留经过确认的新会话；普通请求仍实时检查 D1 会话及当前封禁状态                                  |
| 邮箱验证、密码重置、管理员模拟登录 | 不能替已启用的账户完成第二因子；密码重置不能删除 TOTP 或恢复码                                                    |
| 已发行 PAT、仓库部署令牌           | 继续按原权限、期限和撤销规则运行                                                                                  |
| 已发行 MCP OAuth 凭据              | 撤销网页会话只将绑定的 sessionId 置空，已有 JWT 和刷新令牌继续按当前 consent/封禁规则验证；主动断开应用会立即撤权 |
| 新 MCP 授权                        | 网页登录先完成第二因子，再继续原签名 OAuth 请求、同意页及 PKCE 流程                                               |

TOTP 使用已有 better-auth 插件的算法和加密，不增加发往外部服务的验证码或二维码请求。不提供短信、邮件验证码、记住设备或免验证启用。服务端拒绝这些未开放的调用方式，不能靠隐藏网页按钮限制。

登录挑战十分钟过期，每个挑战最多五次失败；账户级锁定覆盖重复登录及已登录会话的敏感操作验证，跨 IP 不能绕过。已登录验证先在 D1 原子预留尝试，累计十次失败锁定十五分钟，成功验证清零。TOTP 的同一时间步只能成功使用一次；刚登录或刚启用后若立即修改设置，应等待验证器显示下一枚验证码。

TOTP 秘密和恢复码只在当前页面内存中呈现，不写入 URL、浏览器持久存储、查询缓存或日志。认证接口返回 `Cache-Control: no-store`。数据库中 TOTP 秘密加密；恢复码按插件的安全存储方式保存。服务端限制猜测次数，并通过 D1 原子写入防止验证码、恢复码和登录挑战的并发重复使用。D1 的多条依赖写入使用 `batch()` 的事务保证，不假定其支持跨请求交互式事务。

授权变更写入实例审计日志，只含操作者、操作类型和必要标识；不得写入密码、TOTP 秘密、验证码、恢复码或完整 OAuth 请求。第一版尚不声称所有现有机器凭据均携带 MFA 强度。

## 成员的启用和恢复流程

1. 从账户设置进入“安全”，输入当前密码，将密钥导入自己的验证器。
2. 输入验证器生成的验证码确认启用。取消或离开未完成的设置不能把账户标成已启用。
3. 将一次性恢复码保存在账户之外的安全位置。每个码只可使用一次；重新生成整组后，旧码立即失效。
4. 登录时可在验证器验证码与恢复码之间切换。密码错误、挑战失效或过期时重新登录；浏览器刷新不会把未完成的挑战当作已登录。
5. 丢失验证器但还有恢复码时，可用恢复码登录。实例未强制 MFA 时，再以密码和第二因子验证关闭原因子后重新绑定；应预留另一枚恢复码用于这个敏感操作。强制策略下禁止网页关闭因子，丢失验证器后的重新绑定须按下面的独立离线恢复流程处理。

忘记密码与丢失第二因子是两件不同的事。邮件重置、管理员发送的重置链接及 `cloudforge reset-password` 只处理密码，不会解除第二因子；更换密码会撤销基于旧密码建立的未完成双因素挑战。管理员应先保存恢复码，再启用 TOTP；建议至少保留两名有独立因子的管理员。

网页登录挑战绑定实际验证过的密码和因子版本，账户状态变化后不能凭旧挑战重建会话。成员在当前会话修改密码时保留该会话并撤销其他浏览器会话；邮件重置、管理员为其他成员设置密码及 CLI 重置撤销该成员的全部浏览器会话。

备份和迁移实例时应保留 `BETTER_AUTH_SECRET` 的独立安全备份。它同时保护数据库中的验证器秘密和恢复码；单独替换该密钥不能恢复账户，反而会使已有加密材料无法解密。不要把密钥轮换当作丢失验证器的恢复方式。

同时丢失验证器和所有恢复码时，使用下面的独立离线恢复命令。没有网页管理员代解除入口，也不把邮箱或现有机器令牌当作替代因子。恢复不能隐含在密码重置中；本设计不授权运行生产恢复、迁移或部署。

## 独立离线因子恢复

`cloudforge reset-mfa` 通过 Cloudflare 管理凭据直接访问明确指定的 D1。它不依赖可用的网页登录，适用于最后一位管理员失去全部第二因子的情况。应先独立核实申请人的身份及恢复原因，再运行命令。读取预览不证明令牌具有写权限；实际写入仍由 Cloudflare 校验 D1 写权限。

从源码检出目录操作已记录实例：

```bash
yarn cloudforge reset-mfa octocat --name cloudforge --reason "验证器与全部恢复码遗失" --plan
yarn cloudforge reset-mfa octocat --name cloudforge --reason "验证器与全部恢复码遗失"
```

手动部署的实例必须同时明确账户和数据库；不能自动选中唯一账户或唯一安装。包安装方式将 `yarn cloudforge` 替换为已安装版本的 `npx @cybernova2333/cloudforge`。

```bash
yarn cloudforge reset-mfa octocat --account ACCOUNT_ID --database DATABASE_ID --reason "验证器与全部恢复码遗失" --plan
```

预览展示账户、数据库名称与 UUID、安装标记、成员 ID、用户名/邮箱及撤销范围。终端确认默认拒绝；非交互执行必须提供 `--yes --expect-plan <预览摘要>`。目标身份、密码、因子秘密或安装标记在预览后变化会使执行失败，需要重新预览确认。恢复原因写入审计，因此不得填写密码、验证码或其他秘密。

恢复同时撤销 TOTP 秘密、整组恢复码、该成员的全部浏览器会话及会话内第二因子证明、未完成的第二因子挑战及其尝试计数、历史受信设备记录；密码保持不变，之后可凭密码登录并重新绑定。封禁和角色保持不变，代理账户及已封禁成员不接受恢复。未完成的待绑定因子也可清除。PAT、仓库部署令牌与既有 MCP consent/刷新凭据保留，删除网页会话只将其 sessionId 置空；若怀疑凭据泄漏，应另行撤销这些机器凭据。

执行只有一条受目标快照约束的 `INSERT … SELECT`，专用数据库触发器在同一 SQL 语句内完成撤销和 `user.mfa_reset` 系统审计；任一步失败会回滚整条语句。不会依赖 REST 多语句批次的未明确回滚语义，也不部署临时 Worker。预览与实际写入均检查恢复、密码版本和因子版本三个触发器的完整定义；缺少迁移、依赖触发器或定义不匹配时拒绝执行。响应丢失时不自动重试写入，通过公开的恢复事件 ID 只读核验结果；无法确认时必须先核验，不能把未知结果当作未执行。

旧因子验证、旧敏感修改和旧会话密码轮换有凭据/因子代际及会话检查，不能在恢复后重建有效的第二因子会话。密码登录在验证前捕获当前认证代际，离线恢复推进代际后，旧证明不能继承新版本；若请求在恢复完成后才读取当前凭据，它仍可按此时无因子的账户状态正常登录。这里不承诺取消所有发起时间早于恢复的网络请求。管理员强制策略的启用、受限会话与恢复边界见下文。

## 当前浏览器的认证证明

服务端分别记录主要验证方法与时间、第二因子方法与时间，以及认证代际和外部来源。密码、OIDC、邮箱验证、管理员模拟登录、验证器验证码和恢复码分别记录，不能相互冒充。有效 OIDC 或密码主因子加真实本地第二因子可显示双因素强度；近期敏感授权仍另查本地密码。恢复码与验证器是不同的方法，不将恢复码标为验证码。

账户安全页的“当前登录”展示本浏览器实际完成的验证。旧会话没有记录时明确显示未知；不从账号已启用 TOTP、会话创建时间或续期时间推断验证已经完成。页面续期与消费一次性的敏感操作证明不会改变持久的认证方法或验证时间。该显示只帮助成员理解当前状态，不承担权限检查。

普通 API 与认证框架内部的会话读取共用当前代际判定，包括 OAuth 网页授权继续和原生敏感认证接口。密码实际改变、因子启用/关闭与独立离线恢复推进成员认证代际；旧会话即使仍留有数据库行也不再有效。经授权的当前请求可在同一写入流程中保留或轮换到下一代，不得把任意陈旧 context 直接升级。恢复码整组重生成有独立版本，阻止尚未完成的旧组证明继续登录，单个恢复码正常消费不推进该版本，也不注销其他已有网页会话。

`GET /api/me/authentication` 仅接受当前浏览器 cookie，响应 `no-store`，返回方法、实际完成时间、强度、OIDC 来源标记和用于绑定本次响应的公开会话行 ID。它不返回令牌、密码/因子摘要或内部代际，也不对 PAT/MCP 提供浏览器证明。页面在账号或会话变化时丢弃迟到响应，并核对返回的会话 ID。

认证代际表示凭据变更后的会话有效性，不是管理员强制策略的版本。实例可按下文策略强制成员完成本地 MFA，OIDC 来源另受绑定及配置代际约束。既有 OAuth JWT/刷新凭据不追补虚构的 MFA、AMR 或 ACR 声明；PAT 和部署令牌仍遵循原机器凭据规则。

## 最近身份验证

新建个人访问令牌、部署令牌、授予 MCP 代决权限、邀请成员、配置团队、增删仓库协作者及站点管理写操作，需要五分钟内真实完成的当前密码验证；已启用 TOTP 的账户还需要五分钟内真实完成的 TOTP 或恢复码验证。原生管理员接口、修改密码、OAuth 网页授权和应用/授权管理使用相同判定。明确拒绝 OAuth 请求仍走原生会话和签名检查，不要求重新验密。普通业务协作、读取、退出及个人机器凭据撤销保持可用。站点 Setup 诊断不要求重新验证。

遇到门槛时，页面保留原表单并提示重新验证。`POST /api/auth/reauthenticate` 只接受浏览器 cookie 和匹配的公开 sessionId，检查当前密码；账户已启用因子时，同次还须提交验证器或恢复码。失败不会刷新任何证明。成功只更新原会话的真实方法与时间，不更换 cookie，也不生成可用于关闭因子/重生成恢复码的一次性 `mfa_verified_at`。那两个操作仍须独立消费原来的五分钟一次性因子证明。

重验在 D1 预留跨 IP、跨会话的账户尝试预算，TOTP 与原登录共享时间步防重放，恢复码以比较并交换单次消费。最终证明写入检查会话存活、封禁、密码、因子、恢复码组和认证代际；模拟身份不能升级为真实身份。PAT 和部署令牌的实际条件插入再次检查最近证明，不能靠请求入口较早的结果越过已撤销的会话。

团队修改和协作者增删还把原浏览器证明与ACL代数带到最终SQL，按数据库当前时间检查近期证明与会话期限，并重查原OIDC来源、密码账户、因子和目标身份；重复操作也须通过权威检查。写点冲突返回409，不能作为“尚未执行的近期验证挑战”自动重试。具体覆盖范围见[授权管理写入](permissions.md#当前授权管理写入)。

并发受阻请求共享一次验证；取消或账号/会话变化会取消等待的操作。只在服务器明确返回尚未执行的最近验证错误时，浏览器最多重试一次，并携带原会话 ID 供服务端核对。流式请求与不确定的网络失败不自动重放。OAuth 顶层授权可经 `/login/verify` 回到原始站内请求；该路径位于已有保留的登录前缀下，不占用成员用户名。重验表单不把密码或验证码放进 URL、查询缓存或持久存储。

## MCP 授权的撤销代际

每个成员与 OAuth 应用有独立持久授权代际，新 consent、授权码、刷新令牌及 JWT 的 `cf_grant` 声明继承同一代。断开连接和原生删除 consent 在数据库写入时轮换该代际；MCP 同时核对当前代际和对应 consent。原生用户资料和令牌内省也检查当前授权，不能只靠签名判定已撤销令牌仍有效。重新连接同一个应用不能恢复旧 JWT、旧授权码或旧刷新令牌，在途旧 consent/access/refresh 写入也不能成为新授权；不带刷新令牌的 opaque 凭据同样受数据库围栏限制。

迁移前没有代际声明的 JWT/刷新凭据，仅在实例策略版本仍为 `0` 且该成员与应用从未撤销时保持兼容；首次撤销留下永久旧凭据失效标记，后续重新同意也不清除此标记。更改密码或撤销网页会话仍遵循已有 OAuth 保留规则，不把浏览器证明冒充成 OAuth 的 MFA 强度。实例策略变更通过独立策略版本与授权代际撤销旧 OAuth 授权。

## 管理员认证策略

管理员可在站点管理页要求所有人类成员启用双因素验证。策略以独立版本记录，默认版本为 `0`、不强制 MFA；每次启用或关闭都推进版本。比如尚未绑定验证器的成员在策略启用后登录，只能进入绑定、必要的身份验证与退出流程；注册因子本身不代表已完成当前会话验证。已绑定成员的旧会话也需重新验证，不能在读取会话时自动获得新策略权限。

浏览器读取自己的策略状态时只得到当前会话适用的通道：

| 通道             | 可见行为                                                                         |
| ---------------- | -------------------------------------------------------------------------------- |
| `enroll_mfa`     | 强制策略要求绑定因子；完成首次绑定后仍须按当前策略联合重验，并先保存一次性恢复码 |
| `reauthenticate` | 会话版本落后或证明不足；前往 `/login/verify`，成功后回到经校验的站内地址         |
| `full`           | 会话已满足当前策略，可按原仓库权限访问；敏感操作仍另查五分钟内的真实证明         |

普通访问不会每五分钟强制重新登录；五分钟是敏感操作证明的新鲜度要求。受限通道由服务端逐入口限制，网页提示不替代权限检查；`GET /api/me/authentication-policy` 返回当前浏览器的通道，不给 PAT 或 MCP 凭据颁发浏览器证明。

修改策略的管理员须先绑定因子，并在五分钟内通过当前密码及验证器或恢复码联合验证。页面先请求影响预览，展示未封禁人类成员、需首次绑定的成员、执行者之外的未过期浏览器会话、成员 OAuth 连接及机器凭据数量。关闭策略时“需首次绑定”数量为零。PAT 和部署令牌数量按到期时间统计，不表示持有者或仓库权限仍然有效。

预览绑定当前会话、凭据与因子代际、策略版本、目标值及影响数量快照，两分钟过期、只能消费一次；同一会话重新预览会替换旧预览。它确认汇总数量，不列出或绑定逐个受影响成员的名单。执行还须明确确认离线恢复方法；预览期间角色、验证证明或影响数量变化时，拒绝执行并要求重新预览。

策略写入使用 D1 条件写与声明生成的触发器，在同一语句中推进版本、消费预览、撤销 OAuth 授权及写入审计；最终写点重新检查会话存活、管理员身份、封禁、真实证明及各代际，比较并交换（CAS）失败不会触发这些副作用。仅执行者符合当前联合证明的会话可以迁移到新版本，其他浏览器即使在关闭策略后也不能直接沿用旧版本。启用和关闭策略都需要这套授权流程。

受限 cookie 不能读取内部仓库，公开仓库仍按匿名权限读取。原生认证接口和 OAuth 续接也检查策略；明确拒绝 OAuth 授权仍保留原签名与会话检查，不能借此同意授权。开启强制策略期间禁止管理员模拟身份及关闭个人因子。

PAT 和部署令牌保留为非交互机器凭据，既有凭据使用仍按原范围、权限、到期和撤销规则验证，策略切换不会让 Git 自动化输入验证码；创建新凭据仍需当前策略合格的浏览器会话及近期验证。既有成员 OAuth 同意、授权码及访问/刷新凭据在每次策略切换时撤销，包括从强制切回自愿；JWT、opaque 令牌、用户资料和内省入口也核对当前策略代际，重新连接应用不能恢复旧凭据。成员需完成当前要求后重新授权。

离线 `reset-mfa` 可以清除遗失因子，但保留实例策略。最后管理员使用同样的独立离线恢复流程：运行前明确账户、安装或数据库、成员和审计原因；恢复后凭原密码进入绑定通道，确认新因子、保存恢复码，再联合重验，才能恢复管理权限。此恢复不自动撤销既有 OAuth/PAT/部署令牌，也不声明这些凭据满足 MFA；怀疑泄漏时需另外撤销。

实现入口为 `worker/src/auth/policy.ts`、`policy-management.ts`、`worker/src/db/auth-policy-triggers.ts` 与 `worker/src/auth/http/authentication-policy-router.ts`。相应认证策略、会话、OAuth 与审计测试位于 `worker/src/__tests__/authentication-policy*.test.ts`，验证版本围栏、陈旧预览、联合证明及机器凭据边界。新增表、会话列和触发器来自生成迁移 `0056`；生产迁移和部署需单独明确授权。此说明描述代码行为，不将提交、推送或本地验证视为线上已启用。

## OIDC 显式绑定与 SSO 登录

已有成员先显式绑定，再由管理员明确发布登录能力。公开 JSON `OIDC_PROVIDER` 与独立 secret `OIDC_CLIENT_SECRET` 默认不启用；`loginEnabled` 缺省或 false 继续保持只绑定及旧摘要兼容。启用登录须设 true、提高已登记 provider 的版本并重新预览/发布，不能升级即默默获得登录能力。完整流程和验证边界见 [OIDC 身份绑定与 SSO 登录](oidc.md)。

成员保持本地密码与已启用因子的五分钟近期证明，先消费两分钟预览，再经固定 GET 回调校验外部身份，最后在原会话核对候选并二次确认。固定 `(issuer, sub)` 唯一绑定本地身份，不自动注册或按同邮箱合并；撤销及账户删除保留不可转移的身份记录。回调领取、候选和最终 SQL 写点均检查原会话、证明、凭据/因子/恢复/策略及全局 provider 配置代际。绑定写入自有表，不写 Better Auth 的 `accounts`，不持久化外部 token，不颁发登录会话、不刷新近期证明，也不把外部认证冒记为密码验证。

provider id 不可更换 issuer，已登记 id 的配置变更或停用后重新启用必须提升版本并重新发布。全局配置 generation 使旧部署、预览和候选失效。可靠停用须由活跃本地管理员用近期证明先预览、再发布 `enabled=false`，同样推进 generation；不依赖当前 provider 配置或 secret 有效。清空环境变量只影响当前部署，不替代对旧 Worker 和在途动作的发布撤权。配置缺失或无效时状态降为 `ready=false`，仍可查看/撤销自己的绑定或由管理员发布停用。停用同步退休 digest，确认触发器再次检查 enabled 与配置代际。绑定对应生成迁移为 `0057`–`0059`，SSO 动作及会话来源为 `0060`、`0061`。

登录使用自有 `/api/auth/oidc-sign-in` 原生插件，不注册社会化或 `genericOAuth` provider，不允许 JIT、邮箱关联或直接 ID token 登录。匿名 start 严格检查本站 Origin，使用专用 state/nonce/PKCE 及 HTTPS `__Host-` 浏览器证明。回调仅保存已有绑定的账户候选；complete 必须明确确认，已启用因素者无论策略开关都要本地 TOTP/恢复码。强制 MFA 而尚未绑定因素时不发成员会话，改用本地密码走已有绑定流程。普通 SSO 可记录 OIDC 加本地因素，敏感操作仍只接受五分钟内真实本地密码与已启用因素。

SSO 会话另存不可洗掉的 binding id/revision 和配置 generation。真实密码重验可以更新近期证明，不能清除来源；同账户密码/因素操作导致的会话替换也保留来源。独立本地密码登录才建立无 OIDC 来源的新会话。绑定撤销、provider 发布或停用会原子删除相关 SSO 会话并取消候选，REST 与 SDK 再持续核对来源，缺失或部分来源拒绝。既有独立 PAT/OAuth 凭据仍按各自撤销契约处理，不能把删除浏览器会话称为全部 JWT 撤销。

会话签名 memo 同时绑定原始 cookie 与当前签名 secret 的 SHA256 指纹，只省略重复 HMAC 验证，每次仍查 D1 活会话。Cloudflare [允许只改 bindings 时复用 isolate](https://developers.cloudflare.com/workers/runtime-apis/bindings/#making-changes-to-bindings)，因此 secret 轮换不能借用旧 memo，也不能只靠新部署或滑动缓存 TTL 拒绝旧签名。缓存不全局保留明文 secret。协议 metadata/JWKS 只缓存完成数据，不共享跨请求 I/O。

IdP 的 `iat` 只是签发时间；本应用记录的 OIDC 完成时间、外部 `auth_time`、`amr` 或 `acr` 均不自动等于本地密码/MFA。密码和离线恢复继续可用；若需阻断失窃的 IdP 主因子，须明确撤销绑定或停用 provider，不能假定改本地密码即撤销外部身份。通行密钥仍属后续，需要固定 RP ID、可信 origin、明确 `userVerification` 和恢复边界；默认 `preferred` 不等于强制 MFA。

## 依据与验证

实现以锁定的 better-auth 1.7.7 源码为准，并核对 [twoFactor 官方文档](https://better-auth.com/docs/plugins/2fa)、[账户关联规则](https://better-auth.com/docs/concepts/users-accounts)、[generic OAuth](https://better-auth.com/docs/plugins/generic-oauth) 和 [Cloudflare D1 batch 事务语义](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)。
