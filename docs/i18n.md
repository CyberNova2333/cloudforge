# 界面多语言（中文 / English）

网页界面支持简体中文和英文。语言默认跟随浏览器（浏览器语言以 `zh` 开头就用中文），可以在 **头像菜单 → Language · 语言** 里手动切换；切换后存在 localStorage 的 `go-lang`，并刷新页面。未登录访客在顶栏也能切换。

## 原理

- **源码里的英文原文就是翻译的键。** `t('New repository')` 在中文模式下查 `src/locales/zh/` 的词典，查到就显示中文，查不到就原样显示英文。英文模式下永远原样返回。
- 语言在页面加载时确定、整页生命周期内不变（切换会刷新），所以模块顶层用 `t()` 构造的常量也是对的。
- 后端返回的报错在前端经 `errorMessage()` → `tServer()` 翻译：先按原文精确匹配，再按 `src/locales/zh/errors.ts` 里的 `zhPatterns` 正则匹配。后端代码不改。
- `src/lib/i18n.test.ts` 会扫描整个 `src/`：任何 `t()`/`tn()`/`tx()` 用到的键如果词典里没有，测试失败；占位符在译文里丢了、同一个键在两个区域文件里译法不同，也会失败。

## 用法

```tsx
import { t, tn, tx } from '@/lib/i18n'; // src/lib 里的文件用相对路径：import { t } from './i18n';

t('Save changes'); // 普通文字
t('Created {name}.', { name: repo.fullName }); // 带变量：用 {名字} 占位
tn(count, '{n} file', '{n} files'); // 单复数：n 为 1 用第一个，否则用第二个；{n} 是数量
tx('Use a {link} as your password.', {
  // 句子里夹着元素（链接、<b>、<code>…）
  link: <Link to="/settings/tokens">{t('personal access token')}</Link>,
});
```

词典条目写在对应区域的文件里（`src/locales/zh/<区域>.ts`）：

```ts
export const repo: Record<string, string> = {
  'Save changes': '保存更改',
  'Created {name}.': '已创建 {name}。',
  '{n} file': '{n} 个文件',
  '{n} files': '{n} 个文件',
  'Use a {link} as your password.': '使用{link}作为密码。',
};
```

## 规则

1. **键必须是字面量字符串**（单引号或双引号）。不要用模板字符串、变量或拼接作为键——测试会报错，而且无法翻译。需要变量就用 `{占位符}`。
2. **英文键要和原来显示的英文一字不差**，包括标点（`…`、`’` 等特殊字符照抄）。这样英文界面完全不变，现有测试也继续通过。
3. **要翻译的**：页面上看得见的文字、按钮、菜单项、表头、提示、空状态、toast / flash 消息、`aria-label`、`title`、`placeholder`、`alt`、选项数组里的 `label`、`PageHead` 的 `title` / `lede` / `crumbs` 的 `label`、`usePageHead` / 文档标题。
4. **不要翻译的**：CSS 类名、路由路径、URL、查询参数、API 字段和枚举值（如 `'private'`、`'open'`）、用于逻辑比较的字符串、`console` 日志、用户内容（提交信息、文件内容、Markdown、仓库名、分支名）、AI 生成的内容、产品名（GitOrange、Clef、Fixer、MCP、Git LFS、GitHub）、命令行示例（`git clone …`）。
5. **句子不要拆碎**：`Use a <Link>token</Link> as your password` 这种整句用 `tx()`，让译文可以调整语序；不要拆成三个 `t()`。
6. **单复数**：英文里 `n === 1 ? 'repository' : 'repositories'` 这种写法，改成 `tn(n, '{n} repository', '{n} repositories')`；如果数字和词分开显示，就分别 `t('repository')`、`t('repositories')`，中文两个都译成同一个词。
7. **小心变量名 `t`**：如果作用域里已经有叫 `t` 的变量（`.map((t) => …)`、`const t = …`），先把它改名（如 `th`、`tk`），否则会遮住翻译函数。
8. **`src/lib` 里返回显示文字的函数**：在函数内部用 `t()` 包裹即可。测试在英文模式下运行，返回值不变。
9. **服务端发来的固定文字**（例如 Site admin → Setup 的检查标题和修复建议）：渲染时用 `tServer(text)` 包一层，译文放在 `src/locales/zh/errors.ts`。

## 中文风格

- 简洁自然，参考 GitHub 中文界面。按钮用动词短语（“保存更改”、“新建仓库”），不要“请点击…”。
- 中文里用全角标点（，。：；？！“”），省略号用 `…`。
- 中文与英文单词、数字、占位符之间加一个空格：`{n} 个仓库`、`评审 Agent`、`Git LFS 文件`、`在 {branch} 上`。
- 译文里的占位符 `{xxx}` 必须原样保留，个数和名字都不能变。

## 区域与文件

每个区域一个词典文件，汇总在 `src/locales/zh/index.ts`：`common`（通用词）、`shell`（侧栏、顶栏、菜单、搜索，以及登录、初始设置、邀请、授权、404、公开仓库首页）、`repo`（代码、提交、仓库列表与设置）、`pulls`（拉取请求页面）、`review`（评审、自动合并、PR 列表与看板、发行版与标签）、`actions`（Actions、洞察、健康度）、`agents`（Agent）、`approvals`（待审批、首页）、`admin`（站点管理、个人设置）、`lib`（`src/lib` 与 `src/components/ui`）、`errors`（服务端消息）。

新增界面文字时：用 `t()` 包住英文，在对应区域文件里加上中文，跑一下 `src/lib/i18n.test.ts`。列出某些文件里还没包住的英文：

```bash
node scripts/i18n-strings.mjs src/pages/Home.tsx
```

列出某些文件用到、但词典里还没有的键（输出可以直接粘贴进区域文件再填中文）：

```bash
node scripts/i18n-missing.mjs src/pages/Home.tsx
```
