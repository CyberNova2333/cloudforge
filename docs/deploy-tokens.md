# 仓库级 HTTPS 部署令牌

## 目的与范围

部署机、镜像任务和发布机器人只应持有一个仓库的凭据，而不是成员能访问的全部仓库的个人访问令牌。本功能提供仓库级 HTTPS 部署令牌，供标准 Git 和 Git LFS 使用；不提供 SSH，不用于网页登录、REST 或 MCP。CloudForge 仍在 Worker 内换取短期 Artifacts 凭据，部署令牌本身不会转发到 Artifacts。

## 权限与生命周期

- 仓库管理员在仓库设置中创建、查看元数据和撤销令牌。协作者的写权限不足以管理令牌；所有管理员可以撤销该仓库的任何令牌。
- 默认只读：允许 clone/fetch 和 LFS 下载。选择可写后，另允许普通分支、标签的推送和 LFS 上传；没有管理员权限，不能推送默认分支、受保护分支或内部 `refs/pull/*`。仓库当前默认分支必须已经存在，才能用部署令牌推送；否则既有后处理会把第一个普通分支提升为默认分支，绕过这条边界。空仓库先由管理员初始化。
- 令牌绑定不可变的 repository id，仓库重命名不扩大授权；即使创建者拥有多个仓库或站点管理员权限，令牌也不能访问第二个仓库。携带错误令牌访问公开仓库同样拒绝，不回退为匿名读取。
- 令牌是显式部署身份，不冒充创建者执行推送。推送事件、Actions 和 Webhooks 的个人 actor 为空；部署推送另记带令牌 id 的系统审计事件。创建者仅用于签发责任和当前授权检查。
- 每次 Git/LFS 认证都检查令牌存在、未到期，创建者存在、不是代理、未封禁且仍有该仓库管理权。失去管理权或封禁期间令牌被拒绝；若恢复权限，未撤销且未到期的令牌可恢复使用。需要永久停用时撤销令牌。
- 默认有效期 30 天，可选 1–366 天，不提供永久有效选项。到期时刻起拒绝认证。撤销删除令牌记录，后续请求立即拒绝；仓库或创建者删除时级联删除。
- 每仓库最多保留 50 个令牌（含过期令牌），用单条条件插入原子约束并发创建；先撤销不再使用的令牌再创建。列表不返回令牌哈希。

## 凭据与接口

使用 `crypto.getRandomValues` 生成 32 字节随机值，格式 `cfd_` 加 64 位十六进制。数据库只存 SHA256 哈希，明文仅在成功创建时返回一次。管理响应使用 `Cache-Control: no-store`。前端仅在当前页面内存显示明文，不放入 URL、localStorage 或查询缓存；关闭提示、撤销该令牌或离开页面后清除。

管理 API 使用现有网页登录会话及仓库管理员检查：

| 方法   | 路径                                           | 行为                                                                             |
| ------ | ---------------------------------------------- | -------------------------------------------------------------------------------- |
| GET    | `/api/repos/{owner}/{repo}/deploy-tokens`      | 返回令牌元数据数组                                                               |
| POST   | 同上                                           | `{ name, scope: 'read' \| 'write', expiresInDays }`，返回 `{ token, plaintext }` |
| DELETE | `/api/repos/{owner}/{repo}/deploy-tokens/{id}` | 仅在路径仓库内撤销，返回 `{ ok: true }`，不存在时 404                            |

元数据为 `id`、`name`、`scope`、`createdById`、`createdAt`、`expiresAt`、`lastUsedAt`；时间是 ISO 字符串，未使用时 `lastUsedAt` 为 null。名称去除首尾空格后为 1–100 字符。创建和撤销记 `deploy_token.created` / `deploy_token.deleted`，成功推送记 `deploy_token.pushed`；审计只有 id、范围和时间等事实，没有凭据或哈希。

Git 使用现有 HTTPS 地址和 HTTP Basic：用户名可填 `deploy`，密码填部署令牌。优先让凭据管理器保存密码，不把令牌写进 remote URL、脚本日志或 shell 历史。Git LFS 使用同一凭据；默认 Git/LFS 协议与个人令牌兼容。

## 风险和平台边界

可写令牌是仓库代码写权限。持有者可以在普通分支提交工作流并触发 Actions，工作流可使用该仓库获准使用的仓库级和实例级 secrets；它不代表“只能上传构建产物”的隔离权限。只需拉取部署代码时使用只读令牌。

撤销不能取消已开始的 Git 请求，也不能撤回已经签发的 R2 LFS URL（当前最长 15 分钟）；新 Git/LFS 请求会重新认证。权限检查与长时间传输之间也存在这一请求内窗口；管理员并发修改默认分支或保护规则不会追溯已经开始的推送。本轮不改变既有分支保护规则，不提供对每个 ref 的令牌范围配置。

Cloudflare [Artifacts Git protocol](https://developers.cloudflare.com/artifacts/api/git-protocol/) 的 read/write 范围用于上游短期凭据；部署令牌的仓库限制和分支约束由 CloudForge 执行。D1 的单条条件写入用于并发配额，涉及多条写入时遵守 [D1 batch 的事务语义](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)。

## 验证计划

真实 D1 测试覆盖管理权限、跨仓库撤销、并发配额、到期边界、创建者封禁/撤权/删除、代理拒绝、只存哈希和审计不泄密。Git/LFS 测试覆盖只读与可写、跨仓库（含公开仓库）拒绝、默认/受保护/内部 ref 禁止、推送身份及后续事件、REST/MCP 不接受。网页检查覆盖默认只读、一次性明文、撤销、错误状态及移动布局。
