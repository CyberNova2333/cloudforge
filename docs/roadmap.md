# CloudForge 定位与路线图

本文记录项目的定位、到目前为止做了什么、还没做完什么，以及接下来的规划。路线图随实现推进更新。

## 定位

CloudForge 是一个**单租户、自托管在 Cloudflare 上的 GitHub Enterprise Server 式代码平台**，面向想自己掌握代码与数据的团队：

- **一个实例一个组织**：部署在自己的 Cloudflare 账户里，一个 Worker 同源提供 API、网页（React SPA）和 git 端点；元数据在 D1，git 对象与引用在 Cloudflare Artifacts，LFS 与 Actions 日志/缓存在 R2，Actions 作业跑在 Cloudflare Containers。没有服务器要运维。
- **GitHub 的日常协作功能**：仓库、分支、拉取请求、Actions（兼容 GitHub 工作流语法与常用 action）、LFS、发行版、议题、通知、Webhooks 与提交状态、审计日志。
- **差异化：AI 代理参与的合并流程**：审查代理（每个代理是一个带 `AGENT.md` 的仓库）按需审查每个头部提交，提出需要人决定的问题或修改请求；CloudForge 自己做变基 + 快进合并、AI 冲突解决、PR 叠放（stacking）判定、合并队列与自动合并；代理从人的决定中学习（更新自己的知识）；编码代理通过 MCP（OAuth 2.1）直接领取议题、开 PR、读状态。
- **目标用户**：想从 GitHub 迁出、又想要“代理审查 + 自动落地”工作流的中小团队；也适合作为个人或实验室的私有代码平台。

需要提前接受的平台限制：不支持 SSH（Workers 不能监听 22 端口，只能 HTTPS + 令牌）；新建的 Artifacts 仓库上限 1 GB、推送只支持协议 v1（大仓库要用 LFS）；D1 单线程、每条语句最多 100 个参数（高写入功能都按批量写入和后台处理设计）。

## 2026-10-25 集成进展

### Webhooks 与提交状态补完

已完成原路线图指定的立即下一步：

- **网页：仓库设置 → Webhooks**：列表、新建、编辑、删除、密钥保留/替换/移除、投递记录、重新投递、测试 ping。
- **网页：检查框与检查徽章**：展示外部状态及 Actions，只有外部 CI 时也能查看；包含描述、安全详情链接及移动布局。
- **网页：访问令牌说明**：Bearer 上报用途及只读限制。
- **MCP 工具**：`cloudforge_create_commit_status`、`cloudforge_get_commit_status`，共用 REST 输入校验，遵守当前仓库权限；普通连接发现的工具数量为 31。
- 中文翻译、桌面/移动/暗色截图及页面交互检查。

导入审计同时补修了初始化租约、受保护推送、Git 命令解析、通知撤权、密钥白名单并发替换、Actions 故障降级并发及名额回收、Webhook 批量入队/响应读取/签名/租约/耗尽状态/地址检查、提交状态时间戳并列，以及内部 PR 引用的清理进度。新测试进入 CI；行为变更见 `docs/updating.md` 和 `docs/architecture.md`。迁移 `0048` 由 Drizzle 生成，为 Actions 状态/运行添加索引，避免容量检查扫描全部历史作业。

后续可做（`docs/webhooks.md`“以后”）：实例级 webhook、按分支过滤事件、表单编码请求体、连续失败自动停用、**必需检查**（与分支保护规则一起做）。

### 已交付功能里明确“这一版不做”的

- 议题：里程碑、议题模板、跨仓库引用 `owner/repo#N`、直接推送到默认分支时提交信息里的关闭关键字、拉取请求的标记。
- 通知：提交、发行版、Actions 失败的通知；回复邮件即评论；每日摘要邮件；编辑正文时新增的 @ 不通知。
- 集成：仓库级 HTTPS 部署令牌已完成；SSH 部署密钥不在平台能力范围内。Webhook 负载只是 GitHub 字段的子集。

### 交付相关

- 原始 `cloudforge-all.bundle` 已导入本地；保留四个分支的完整历史。新交付 bundle 包含导入成果与本次补修，远端推送另需明确指示。
- 部署时需按实例已应用记录执行后续迁移：集成功能至 `0048`，因子、恢复与近期认证至 `0055`，管理员强制 MFA 策略增加生成迁移 `0056`，OIDC 显式绑定增加生成迁移 `0057`，全局停用及确认触发器围栏增加生成迁移 `0058`、`0059`，SSO 动作、私有会话来源及原子签发约束增加生成迁移 `0060`、`0061`。自己的 `wrangler.jsonc` 中还需 `triggers.crons` 的 `*/5 * * * *`（见 `wrangler.jsonc.example`）。迁移、部署和线上策略变更分别授权与验证，不由本地交付自动执行。

## 规划

### 第一阶段：日常协作必备（进行中）

1. 议题 —— 已完成（里程碑、模板待做）。
2. 通知 —— 已完成。
3. 集成接口 —— 提交状态、Webhooks 后端、网页与 MCP 工具、仓库级 HTTPS 部署令牌已完成。部署令牌默认只读、限一个仓库、1–366 天有效、可撤销并审计；管理网页和 Git/LFS 共用独立部署身份。设计与边界见 [部署令牌](deploy-tokens.md)。

本阶段的议题模板、里程碑及 Webhook 扩展仍按上面的明确后续项保留。已进入第二阶段；中文[认证设计](authentication.md)明确管理员强制策略、登录恢复、旧会话与机器凭据的边界。

### 第二阶段：单租户企业部署的门槛

4. **SSO 与双因素认证（进行中）**：已实现自愿 TOTP、一次性恢复码、账户安全页、登录挑战及 MCP OAuth 续接。独立 `reset-mfa` 离线恢复要求明确目标、预览确认、单语句撤销和审计。会话统一记录真实方法与完成时间，凭据代际在普通 API 与原生认证入口共用；敏感操作与 OAuth 网页授权要求近期联合重验。代码现已包含管理员强制 MFA、独立策略版本、两分钟一次性影响预览及最终写点 CAS；未绑定或证明不足的会话只获得绑定/重验通道。每次策略切换撤销既有成员 OAuth 授权，已有 PAT/部署令牌使用保持原规则，新增凭据仍受策略与近期验证约束；离线恢复不会关闭实例策略。完整边界见[认证设计](authentication.md#管理员认证策略)，生产迁移、部署及线上启用另行授权与验证。[OIDC 身份绑定与 SSO](oidc.md) 已包含管理员部署配置预览/发布与全局停用、已有成员近期本地证明下的绑定、候选二次确认和撤销；回调、候选及最终写点均受原会话和全局配置代际围栏保护。停用需本地管理员近期证明下发布 `enabled=false` 并推进配置代际，不依赖有效部署配置；清空 env 不能替代全局撤权。已绑定仍可查看/撤销，重启用须更高版本。提供商登记及身份不可复用，不持久化外部 token。已有活动绑定可在管理员升版明确发布 loginEnabled 后使用独立 SSO 登录：回调只保存候选，二次确认及本地因素完成后才签发 SDK 会话，来源在重验和同账户会话替换中保留，撤销及配置发布持续约束这些会话。敏感操作仍要求近期本地密码；无 Web Locks 的浏览器继续密码登录。SSO-only、受信外部 MFA、多 provider 和通行密钥仍为后续。
5. **多团队与细分角色（设计阶段）**：维持单实例、单组织的定位，设计多个团队与 read / triage / write / maintain / admin 五级仓库角色。当前仍是单共享团队和 read/write/admin 三个公开权限布尔值，阶段 A 已增加内部命名能力兼容层并保持原结果，阶段 B 已加入只读预检、受限兼容schema及首个过渡运行时（D1 协议准入，新角色保持关闭）；[权限设计草案](team-access-design.md) 明确现有 internal 可见性、创建者管理权、协作者回填、机器凭据上限和即时撤权，新角色授权模型尚未开放。接下来补齐在途操作的写点授权、排空及版本化发布/回滚核验，再实现团队成员关系及 API/界面，最后验证所有访问入口一致。
6. **分支保护规则**：必需检查（Actions 作业与提交状态 context）、所需批准人数、CODEOWNERS、受保护标签、规则是否约束管理员；替换现在的固定推送保护。
7. **运维**：每个仓库导出 git bundle + D1 导出的备份；显示存储用量（Artifacts 1 GB 上限）；仓库归档与转移。

### 工程习惯（沿用）

一个功能一个分支，先写中文设计文档；每个提交带相关测试；改行为时同步所属专题，涉及未来 Agent 的操作规范时更新 `AGENTS.md`，再用 `yarn agents:sync` 生成 `CLAUDE.md` 引用入口及技能副本。新测试文件登记到 `.github/workflows/ci.yml`；交付 bundle 保留从实际远端基线起的相关分支历史，并验证恢复结果。
