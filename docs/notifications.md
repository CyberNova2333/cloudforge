# 通知（Notifications）

通知告诉一个人“哪里有事和你有关”：你开的议题有了新评论，有人 @ 了你，拉取请求被合并，你被指派了议题。每个人有一个收件箱，每个议题或拉取请求在收件箱里是一条“会话”，有新动静时这一条回到顶部并标为未读；与自己直接相关的动静也可以发邮件。本文是设计说明，也是行为说明：实现以它为准，改行为时一并更新。

评审意见的待办（Approvals 收件箱）不变，仍然是“需要你做决定的评审意见”；通知是另一回事：动静，而不是待办。

## 谁会收到

一次动静发生在某个议题或拉取请求（会话）上，由某人（行动者）触发。收件人是：

1. **订阅了这条会话的人**（`notification_subscriptions`）：作者、评论过的人、被 @ 过的人、被指派的人自动订阅；也可以在页面上手动订阅或取消订阅。
2. **关注（Watching）这个仓库的人**（`repository_watches`）：仓库顶部选择“关注”后，收到这个仓库所有议题和拉取请求的动静。默认（没有记录）是“仅参与”：只收到自己订阅的会话。选择“忽略”则这个仓库的任何动静都不通知。
3. **这次被直接点名的人**：正文或评论里 `@用户名`（新建和评论时；代码、邮箱地址、单词中间的 @ 不算），被指派。点名会重新订阅，哪怕之前取消过。

然后排除：行动者本人；取消订阅了这条会话的人（除非这次被点名）；忽略这个仓库的人；Agent；已封禁的人；**对这个仓库没有读权限的人**（私有仓库里 @ 一个看不到它的人不会通知他，也不会泄露标题）。权限按 `permissionsFor` 的同一规则在投递时判断，收件箱读出时还会再按 `visibleTo` 过滤，失去权限后已有的通知也不再显示。

触发通知的动静：

| 会话     | 动静                                                             |
| -------- | ---------------------------------------------------------------- |
| 议题     | 新建、评论、关闭（含被拉取请求的关闭关键字关闭）、重新打开、指派 |
| 拉取请求 | 新建、评论、合并、关闭、重新打开                                 |

新建时只有关注仓库的人和被点名的人会收到（会话还没有其他订阅者）。

## 收件箱

`notifications` 每人每条会话一行（唯一键 `(user_id, thread)`，`thread` 为 `issue:<id>` 或 `pull:<id>`），每次动静 upsert：记下这次的原因（`mention`、`assign`、`author`、`participating`、`watching`）、动静类型、行动者、一段摘录（评论的前 280 个字符），标为未读，更新时间置为现在。一次动静对所有收件人只写一条 SQL（`INSERT … SELECT … FROM json_each(?)`），不随人数增加语句。

- 列表：未读 / 全部，可按原因和仓库筛选，按更新时间倒序，分页。
- 操作：标为已读或未读、全部标为已读（可限定仓库）、完成（从收件箱移除，直到下次有动静）。
- 顶栏铃铛显示未读数。写入后向收件人的实时频道 `user:<id>` 发一次 ping，页面即时刷新。

## 邮件

个人设置“邮件通知”：`participating`（默认，与自己直接相关的：被点名、被指派、自己开的或参与的会话）、`all`（再加关注的仓库）、`off`。只发给已验证的账户邮箱，只在实例配置了发信时发。

通知行带 `email_pending_at`：需要发邮件时置上，发件程序认领（置为空）后再发，所以同一待发记录不会因重试重复发；认领后发送失败的邮件不会自动重发。同一会话在发出前的多次动静合并为一封。发件在写入后的 `waitUntil` 里进行；未被认领而遭中断的记录由每日任务补发（只补 24 小时内的，更早的放弃）。

每一封开始发送前，重新读取该收件人的账号、已验证邮箱、偏好、订阅与关注状态，并读取当前仓库及权限。例如一批两封邮件中，第一封发送期间第二位收件人关闭邮件通知，第二封会跳过；不会继续使用整批开始时的资格快照。这是每封的最新状态检查，D1 查询和外部发信之间仍有窗口，不能撤回已交给邮件服务的请求。

事件、原因、操作人和摘录固定为原子领取时的快照；资格与目标邮箱仍逐封刷新。如果等待期间同一通知行收到新事件，旧批次不会读取并重复发送已被另一批次领取的新事件。不同事件的邮件可能交错到达，不承诺跨发送请求的到达顺序。

邮件标题 `[owner/repo] 标题 (#N)`，正文写谁做了什么、摘录、链接，以及“你收到这封邮件是因为……”和设置页链接。

## 接口

- `GET /api/notifications?filter=unread|all&reason=&repo=owner/name&page=&limit=`、`GET /api/notifications/count`
- `POST /api/notifications/read`（`ids` 或 `all`，可带 `repo`）、`PATCH /api/notifications/{id}`（`unread`）、`DELETE /api/notifications/{id}`（完成）
- `GET`/`PUT /api/repos/{owner}/{repo}/watch`（`level`: `participating` | `watching` | `ignoring`）
- `GET`/`PUT /api/repos/{owner}/{repo}/issues/{n}/subscription`、`…/pulls/{n}/subscription`（`subscribed`）
- 个人设置 `notificationEmail`（`GET`/`PUT /api/me/preferences`）

## MCP

`cloudforge_list_notifications`（默认未读）与 `cloudforge_mark_notifications_read`（指定或全部）。

## 网页

顶栏铃铛与 `/notifications` 收件箱；议题和拉取请求侧栏的“订阅 / 取消订阅”；仓库顶部的关注选择；设置 → 通知（邮件）。`notifications` 成为保留用户名。

## 保留

每日任务删除已读超过 90 天、或任何超过 365 天的通知。订阅与关注随仓库、议题、拉取请求、用户删除而级联删除。
