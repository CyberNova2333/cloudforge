# 第二阶段：权限模型、身份隔离与安全边界

CloudForge 在边缘 Worker 入口、仓库权限、外部集成凭据和浏览器敏感操作之间建立明确的隔离墙。理解这些契约，能帮助运维与集成开发者在接入自动化时避开看似“意外实则刻意拦截”的边界。

## 1. 仓库访问矩阵（当前兼容实现）

仓库存在于**个人命名空间**（`/<username>/<repo>`，默认 `private`，所有者可切至 `internal` 或 `public`）或**唯一共享团队命名空间**（`/<team-slug>/<repo>`，默认 `internal`，团队仓库管理员可显式设为 `public`，禁止设为 `private`）。用户名与团队 slug 共用统一的大小写归一化命名空间表（包括通过 better-auth 改名接口及 Agent 软删除保留名）。

| 当前访问身份                    | 读取范围                              | 推送 / 协作写入                                  | 仓库设置与管理 |
| ------------------------------- | ------------------------------------- | ------------------------------------------------ | -------------- |
| 站点管理员（`admin`）           | 所有仓库                              | 允许                                             | 允许           |
| 个人仓库所有者 / 团队仓库创建者 | 对应仓库                              | 允许                                             | 允许           |
| 直接协作者                      | 对应仓库                              | 允许                                             | **拒绝**       |
| 其他有效实例成员                | 所有团队、`internal` 与 `public` 仓库 | **拒绝**                                         | **拒绝**       |
| 匿名访客或已封禁成员            | 仅 `public` 仓库                      | **拒绝**                                         | **拒绝**       |
| Reviewer Agent 账号             | 自有配置仓库 & 被邀请参与的审查上下文 | 仅学习分支允许写自身 `AGENT.md` / `knowledge/**` | **拒绝**       |

- **不泄密 404**：任何无权查看的私有仓库在网页、REST API、搜索、通知收件箱、Git HTTP 与 LFS 中一律返回 `404` 而非 `403`。
- **内部权限兼容层（阶段 A & B）**：目前内部已引入 `can(perms, capability)` 与数据库兼容性 `role` / `revision` / `access_generation` / `access_runtime_state`，但新五级角色（`read`/`triage`/`write`/`maintain`/`admin`）与多团队成员表**仍未开放授予**，当前运行时保持上述三值模型（详细设计边界见仓库 `docs/permissions.md` 与 `docs/team-access-design.md`）。
- **个人资料邮箱隔离**：只有站点管理员与成员本人能在成员接口看到账户邮箱，其他成员统一收到 `null`；Git 提交对象本身附带的 author/committer 邮箱属于代码历史，不受账户隐匿规则改写。

## 2. 凭据家族与使用范围边界

| 凭据类型                    | 适用入口                                                               | 明确不适用范围与吊销边界                                                                                                                                                    |
| --------------------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **浏览器 Cookie 会话**      | React SPA、全部 `/api/*` 管理端点、WebSocket `/api/live`               | 根据 `BASE_URL` 协议强制启用 `__Secure-` 前缀；同源写入检查拦截跨站 POST                                                                                                    |
| **个人访问令牌（PAT）**     | Git HTTP、Git LFS、`/api/.../statuses/{sha}` 与 `commits/{ref}/status` | **不用于网页或其它 REST API**；使用成员实时权限与令牌 scope（`read` / `write`）的交集                                                                                       |
| **仓库部署令牌（`cfd_`）**  | 仅绑定单个不可变 `repository_id` 的 Git HTTP & LFS                     | **不登录网页、REST 或 `/mcp`**；默认只读，可写令牌不可推默认分支/受保护分支/空库首个分支/`refs/pull/*`；每次请求复查签发者是否仍在职管理员；每库上限 50 个，有效期 1–366 天 |
| **OAuth 2.1 JWT（`/mcp`）** | 仅 `POST /mcp`（受众 `<origin>/mcp`，访问令牌 1 小时）                 | **不用于网页/REST**；需经过 PKCE 同意屏幕，断连删除 consent 后下一次 `/mcp` 调用立即拒绝                                                                                    |
| **Reviewer Agent**          | 仅内部无凭据模型上下文                                                 | `session.create.before` 与 Token 入口禁止登录、禁止创建 PAT、禁止作为普通协作者邀请                                                                                         |

## 3. 强安全假设与输入约束

- **管理员近期认证与策略版本**：修改共享团队、增删协作者、变更实例设置或仓库敏感设置、切换强制 MFA 策略或管理 OIDC 提供商配置时，除了验证会话有效外，还要求**近期本地密码与已启用第二因子证明**，并在最终 D1 写入 SQL 上对照 ACL / Policy / OIDC 代际做条件检查，策略冲突统一返回 HTTP `409`（详见 `docs/authentication.md` 与 `docs/oidc.md`）。
- **OIDC 绑定与单点登录隔离**：管理员须先在近期本地认证下显式配置并发布 OIDC 提供商（`enabled` 与独立 `loginEnabled`），已有成员先行绑定身份，且每次 SSO 回调先停留在临时候选页经二次确认与本地 MFA 才签发会话（保留 `sso` 来源标签，高危写操作仍要求近期本地密码）；停用发布全局 `enabled=false` 立即阻断既有 SSO 登录能力。
- **请求体与存储上限**：`/api/auth/*` 限制请求体 `64 KB`，其余 `/api/*` 与 `/mcp` 限制 `1 MB`；仓库 Webhook 校验拒绝 `localhost`、`.local`、`.internal` 及私有/保留 IP 字面量（Workers 侧不预解析全部 DNS）；审查深度沙箱跳过二进制、符号链接、lockfile 与 `.orangeignore` 模式匹配文件（详见仓库根 `docs/configuration.md` 与 `docs/webhooks.md`）。
- **用户删除防护**：由于 `repositories.owner_id` 关联个人与团队仓库创建者，数据库与触发器要求管理员先通过正常仓储清理流程删除名下仓库，否则阻止孤儿级联删除用户。
